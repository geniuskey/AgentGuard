# 명시 권한 규칙 비교

Agent Guard는 실행 중인 Claude Code의 최종 승인 결정을 재현하지 않는다. 미리보기, 파일 트리, Simulator는 명시된 규칙의 근사 비교다.

## 도구와 컨텍스트

- Read와 Edit를 별도로 비교한다. Edit 전용 Deny를 읽기 차단으로 표시하지 않는다.
- Read Deny는 같은 경로의 Edit에도 반영한다.
- 프로젝트 루트와 사용자 홈을 전달해 `~/…`, `//c/…`, 사용자 설정의 `/…` 경로를 해석한다.
- 지원하는 단순 패턴의 비교 순서는 `deny > ask > allow`다. 관리자가 `allowManagedPermissionRulesOnly`를 설정하면 하위 scope 규칙은 제외한다.
- 직접 자식 패턴의 `*`는 `/`를 넘지 않는다.
- 일치 규칙 없음은 `null`이며 Ask가 아니다. 지원하지 않는 패턴이나 컨텍스트 부족도 판정하지 않는다.

## 한계

실행 모드, CLI 플래그, 신뢰 상태, 실제 심볼릭 링크 대상, 훅, 서버/레지스트리 관리 정책까지 확인하지 않는다. gitignore 부정·문자 클래스 등 지원하지 않는 패턴이 관련 도구에 있으면 판정을 보류한다.

명령 비교기는 단순 명령만 비교한다. 복합 명령, 인용, 치환, 리다이렉션, 알려진 래퍼·별칭은 셸 파서를 재구현하지 않고 판정 불가로 반환한다. 실제 승인이 필요한지는 Claude Code에서 확인해야 한다.

## 편집과 보존

`permissions.defaultMode`는 경로 규칙과 독립적인 실행 모드 설정이다. 경로 규칙을 저장해도 삭제하거나 바꾸지 않는다.

범용 보안 프로필 선택 UI는 제거했다. 이전 프로필 이름은 과거 메타데이터로만 남으며 현재 권한을 설명하지 않는다. 후보 검토는 기존 규칙을 기본 보존하고, 항목별 명시적 교체만 허용한다.
