# 경로 후보 발견과 검토

스캐너는 프로젝트 루트 한 단계의 이름을 관찰한다. 하위 폴더, 파일 내용, 실제 비밀값, 접근 필요성을 검사하지 않는다. 이 결과를 보안 등급이나 권한 권고로 사용하지 않는다.

## 후보 정보

- `candidates`: 경로, 실제 파일/폴더 종류, 패턴에 일치한 근거를 전달한다.
- `denyCandidates` / `allowCandidates`: 기존 API 호환용 이름이다. 적절한 권한을 보장하는 판단이 아니다.
- 자격증명 관련 이름뿐 아니라 `data`, `logs`, `certs` 등도 관찰 대상이다. 공개 데이터나 개발용 인증서일 수 있다.
- 일반적인 작업 경로 이름인 `src`, `tests`, `docs` 등도 실제 읽기/수정 허용 필요성을 확인하지 않았다.
- 파일 종류는 파일시스템에서 전달한다. 확장자가 없는 `id_rsa`, `id_ed25519`도 파일 규칙으로 생성한다.

## 검토 흐름

1. 사용자가 **경로 후보 검토**를 연다.
2. 모든 후보는 기본 미선택이며, 기본 선택값은 Read / Ask다. 어떤 규칙도 자동 추가되지 않는다.
3. 필요한 항목과 Read/Edit, Allow/Ask/Deny를 직접 선택한다. Allow는 확인 절차를 줄일 수 있다.
4. 같은 경로의 기존 규칙은 모두 표시한다. 교체를 명시하지 않으면 보존한다.
5. 선택한 후보를 편집 상태에 반영하고, scope별 저장 Diff를 검토한 뒤 백업 후 저장한다.
6. 무시한 후보는 다음 검토에서 제외한다.

## 위험 점수와 프로필

기존 이름 기반 가중치 함수와 DB 필드는 호환성을 위해 남아 있다. 실제 노출·유출 가능성을 검증한 점수가 아니므로 UI와 내보내는 리포트에 보안 등급으로 표시하지 않는다. 프로젝트에는 후보 수와 루트 한 단계 검사 범위를 표시한다.

서로 차이가 없거나 기존 규칙 전환 의미가 불명확한 Conservative/Balanced/Fast Dev/Custom 선택 UI도 제공하지 않는다.
